# PenTip 产品战略文档（MRD）

---

## 一、产品概述与定位

### 1.1 产品名称

**PenTip**

### 1.2 Slogan

> 记录破万条，体系自形成。

### 1.3 一句话定位

> PenTip 是一个以 Markdown 文件为数据源，以 AI 为智能索引的认知工作台，让碎片知识自动结晶为体系，在创作中自然调用，在思考中持续演化。

### 1.4 核心定位

PenTip **不是**传统笔记软件，也**不是** Obsidian 或 Logseq 的简单融合。

PenTip 的 MVP 目标是：**让 Obsidian 和 Logseq 的用户多一个选择**——
以 Markdown 文件作为数据的真实来源，以 AI 自动整理取代手动双链和文件夹分类，
让内容创作者获得"记录即整理"的体验。Phase 2 再实现超越。

```
用户数据 = Markdown 文件（真实来源）
智能能力 = 数据库 + 向量库（AI 索引）
```

### 1.5 三大核心目标

| 目标                  | 描述                                                       | Slogan 映射            |
| :-------------------- | :--------------------------------------------------------- | :--------------------- |
| **目标1：自动整理**   | 将零散的知识碎片自动整理成体系知识                         | 记录破万条，体系自形成 |
| **目标2：高质量创作** | 基于知识体系输出高质量的创作内容                           | 思考深一度，创作如有神 |
| **目标3：自动推演**   | 自动推演知识体系，帮助用户更全面或深入地形成自己的知识体系 | 知识常推演，认知日日新 |

### 1.6 核心价值

| 价值层   | 用户行为                 | AI 自动完成                                    |
| :------- | :----------------------- | :--------------------------------------------- |
| **记录** | 自由输入，日志流式记录   | 保存为 Markdown 文件，无需关心分类             |
| **整理** | 记录即可，无需主动组织   | 语义拆分、向量化、概念提取、主题聚类、语义关联 |
| **推演** | 查看反思流、时间线、图谱 | 观点变化追踪、模式发现、矛盾检测、知识缺口识别 |
| **创作** | 专注写作，调用智能辅助   | 语义检索、续写/润色/摘要、大纲生成、引用推荐   |

### 1.7 产品哲学

| 理念                 | 说明                                          |
| :------------------- | :-------------------------------------------- |
| **File First**       | Markdown 文件是真实数据源，用户拥有完整控制权 |
| **Local First**      | 数据完全本地可控，隐私安全，离线可用          |
| **AI Native**        | AI 嵌入记录、整理、推演、创作全流程           |
| **Flow → Structure** | 日志流自然输入，知识体系自动生长              |

## 二、市场机会

### 2.1 时代背景

AI 大模型能力快速提升，但存在根本性短板：

- **没有长期记忆**：无法记住用户的历史思考
- **不理解用户**：缺乏个人化上下文
- **无法形成持续认知**：思维碎片难以沉淀为知识体系
- **数据锁定焦虑**：用户不愿将个人思考数据上传云端，也不愿被封闭格式绑定

### 2.2 市场缺口

当前知识工具存在巨大的用户体验断裂：

```
灵感 → 临时记录 → 碎片堆积 → 手动整理 → 知识库 → 创作输出
```

**核心痛点：输入与沉淀之间存在巨大摩擦，整理与推演更是完全依赖用户手动完成。**

现有工具要么擅长输入（低阻力记录），要么擅长沉淀（结构化知识库），要么擅长创作（文档编辑），但没有产品能打通"记录 → 整理 → 推演 → 创作"全流程，且不锁定用户数据。

### 2.3 机会窗口

| 驱动因素           | 说明                                               |
| ------------------ | -------------------------------------------------- |
| 本地 LLM 成熟      | 4B-8B 模型可在消费级设备运行，推理成本趋零         |
| Embedding 成本下降 | 本地向量化成为可能，无需云端 API                   |
| 知识工作者 AI 化   | 目标用户已习惯用 AI 辅助思考                       |
| 隐私意识觉醒       | 用户越来越不愿将个人思考数据上传云端               |
| 文件优先共识       | Obsidian/Logseq 已教育市场：用户希望拥有自己的数据 |

## 三、目标用户

### 3.1 核心用户画像

**画像名称**：内容创作者

| 属性 | 描述 |
| -------------- | ------------------------------------------------------------ |
| 职业 | 写作者、博客作者、自媒体人、技术作者、产品经理、内容运营 |
| 年龄 | 22-40 岁 |
| 核心场景 | 灵感碎片记录 → 自动整理 → 长文写作输出 |
| 现有工具 | Obsidian / Logseq / Notion / 飞书文档 |
| 核心痛点 | 记录容易整理难，双链/文件夹需要手动维护，AI 功能分散在多个工具中 |
| 技术素养 | 中高，熟悉 Markdown，愿意尝试本地优先工具 |
| 付费意愿 | 中高，愿意为提升写作效率和质量付费 |

### 3.2 核心切入点

重点切入 Obsidian / Logseq 的存量用户：

- 他们已建立文件优先的使用习惯
- 他们对数据锁定的警惕性最高
- 他们对 AI 有需求但现有方案需要折腾插件
- PenTip 可以兼容他们的现有工作流（直接打开现有 Obsidian 仓库）

### 3.3 MVP 阶段不做的人群

| 人群 | 原因 |
| ---- | ---- |
| AI 研究员/开发者 | 需求偏技术笔记 + 代码管理，与内容创作者场景差异大 |
| 学者 | 需要文献管理 + 论文推演，属于 Phase 2 目标3 范畴 |
| 学生 | 付费意愿低，非早期增长目标 |

### 5.2 间接竞品

- **AI 聊天工具（ChatGPT、Claude）**：用户将对话作为临时笔记，但缺乏长期存储和关联能力。
- **语音笔记（Voicenotes、AudioPen）**：输入阻力极低，但无知识沉淀。
- **Readwise**：高亮与摘录聚合，但无创作能力。

> **关键差异**：PenTip 是从记录 → 整理 → 推演 → 创作的全流程自动化工具，且不锁定用户数据——用户可以随时用 Obsidian 或其他编辑器打开同一目录继续工作。这是与所有竞品的根本区别。

## 六、产品愿景与核心理念

### 6.1 愿景

PenTip 的目标是成为知识工作者的长期认知伙伴：

```
记录 → 自动整理 → 自动推演 → 高效创作
```

最终形成：**Personal Cognitive Workspace（个人认知工作台）**——一个让用户自由记录、让 AI 自动整理的开放知识环境。

### 6.2 核心理念

#### File First（文件优先）

真实数据源是 Markdown 文件。用户可以直接用文本编辑器打开、修改、备份，完全掌控自己的数据。数据库只是 AI 索引层。

#### Local First（本地优先）

用户必须拥有自己的数据：信任、隐私、AI 长期记忆、离线能力、数据可迁移。

#### AI Native（AI 原生）

AI 不是插件，而是工作流本身：语义拆分、向量化、概念提取、主题聚类、语义关联、反思推演。

#### Flow → Structure（流式输入，结构化生长）

用户以日志流方式自由记录，AI 自动将碎片整理为知识体系——从无序到有序，从碎片到结构。

### 6.3 产品架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                    用户交互层                                    │
│  Journal 视图（日志流）  创作工作台（项目编辑器）  搜索/图谱    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    文件系统层（真实数据源）                       │
│  journal/*.md      projects/*.md      assets/                   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    智能索引层                                    │
│  SQLite（概念/主题/关联）    LanceDB（语义向量）                 │
└─────────────────────────────────────────────────────────────────┘
```

## 七、三大核心目标的实现路径

三个核心目标构成了一个**层层递进、相互支撑**的能力金字塔。下面逐层拆解每个目标的实现路径。

### 7.1 目标1：零散知识自动整理成体系知识

> 解决知识工作者将零散的知识自动整理成体系知识

这是 PenTip 的**立身之本**，也是最核心的基础能力。它通过以下机制实现：

#### 7.1.0 数据流：记录 → 文件 → 索引

```
用户输入 → 写入 journal/YYYY-MM-DD.md 文件
    │
    ▼（后台自动，5 秒延时）
文件变更检测 → 对比 file_index 中的 hash
    │
    ▼
语义块解析 → AI 语义拆分 → 写入 semantic_chunks
    │
    ▼
AI 智能处理 → 向量化（LanceDB）→ 语义关联 → 概念提取 → 主题聚类
```

#### 7.1.1 输入：零阻力捕获

- **Journal 日志流**：用户只需记录，不需要想放哪里、打什么标签
- **语义拆分**：AI 根据内容语义边界自动拆分为独立语义块

#### 7.1.2 整理：自动结构化

| 层次         | 自动完成的工作                        | 用户感知                               |
| :----------- | :------------------------------------ | :------------------------------------- |
| **语义块层** | 向量化存储（LanceDB）、AI 摘要生成    | 每个语义块有摘要，可语义搜索           |
| **链接层**   | 语义相似度计算 → 自动建立语义块间关联 | 语义块底部显示"关联：xxx"              |
| **概念层**   | 高频概念提取                          | 概念列表自动生成，点击可查看相关语义块 |
| **主题层**   | 语义聚类 → 自动生成主题               | 主题列表出现候选主题，用户确认/归档    |

#### 7.1.3 存储：文件优先，数据库索引

- **真实数据源**：Journal 内容追加写入 `journal/YYYY-MM-DD.md` 文件，用户可直接用文本编辑器访问
- **SQLite 索引层**：`file_index` 记录文件元数据和同步状态，`semantic_chunks` 缓存语义块内容（避免频繁读文件）
- **LanceDB 向量库**：`chunk_embeddings` 存储语义块向量，支持语义搜索和相似性匹配
- **AI 处理结果**：概念、主题、语义关联等 AI 产物存储在 SQLite 索引表中，不写回 .md 文件
- 所有数据在本地，离线可用，隐私安全

> **目标1 的验证点**：用户记录 50 条 Journal 条目后，是否能看到自动生成的 3-5 个有意义的主题？主题采纳率 ≥ 60%。

### 7.2 目标2：基于知识体系输出高质量创作

> 基于知识体系输出高质量的创作

这是 PenTip 的**价值放大层**，将整理好的知识体系转化为可交付的成果。

#### 7.2.0 数据流：创作 → 文件 → 索引

```
用户创建项目 → 在 projects/ 下创建目录和 .md 文件
    │
    ▼
用户编写内容 → Markdown 文件保存
    │
    ▼（后台自动）
文件同步 → AI 语义拆分 → 向量化
    │
    ▼
AI 辅助 → 语义检索 → 续写/润色/大纲生成/引用推荐
```

#### 7.2.1 创作工作台（项目编辑器）

- **左侧大纲树**：管理作品结构（项目 → 页面/章节）
- **中间编辑器**：Markdown/富文本编辑，专注内容创作，每个页面对应 `projects/{name}/*.md` 文件
- **右侧 AI 助手**：提供即时的智能辅助

#### 7.2.2 创作场景的 AI 能力（Skills）

| 场景 | 功能      | 输入        | 输出           |
| ---- | --------- | ----------- | -------------- |
| 写作 | 续写      | 光标前文    | 后续内容       |
| 润色 | 润色/改写 | 选中文本    | 优化后文本     |
| 组织 | 生成大纲  | 主题/关键词 | 结构化大纲     |
| 引用 | 插入引用  | 搜索关键词  | 相关语义块引用 |

#### 7.2.3 知识召回

- **语义检索**：在创作时侧边搜索历史语义块，毫秒级召回
- **上下文自动召回**：AI 根据当前写作内容，自动推荐相关的历史语义块
- **一键引用**：搜索结果可一键插入编辑器，带跳转链接

#### 7.2.4 作品生命周期管理

- 作品（Project）是 `projects/` 目录下的独立 `.md` 文件集合，AI 将其内容索引为语义块供检索和引用
- 从主题一键创建项目，AI 自动生成初始大纲

> **目标2 的验证点**：用户能否在 30 分钟内，基于已有笔记完成一篇 2000 字的文章草稿？

### 7.3 目标3：自动推演知识体系

> 自动推演知识体系，帮助知识工作者更全面或深入地形成自己的知识体系

这是 PenTip 的**长期护城河**，让知识管理从"静态存储"升级为"动态演化"。

#### 7.3.0 AI 能力模式

推演引擎依赖 LLM 推理能力，用户可根据需求选择运行模式：

| 模式         | 适用版本 | AI 模型               | 能力范围                                       |
| :----------- | :------- | :-------------------- | :--------------------------------------------- |
| **本地智能** | Core 版  | Qwen 系列（本地运行） | 基础推演：时间层追踪、概念演化摘要、模式发现   |
| **云端智能** | Pro 版   | OpenAI 兼容 API       | 完整推演：含矛盾检测、知识缺口识别、跨领域关联 |

> 两种模式共享相同的推演框架和数据模型，仅推理能力不同。用户可随时切换。

#### 7.3.1 时间维度的推演（时间记忆引擎）

| 能力             | 实现方式                                     | 用户价值                   |
| :--------------- | :------------------------------------------- | :------------------------- |
| **观点变化追踪** | 对比同一概念在不同时间的语义块，分析观点变化 | 看到自己的认知进化轨迹     |
| **兴趣漂移检测** | 按时间统计各概念/主题的语义块数量变化        | 发现关注焦点的转移         |
| **演化摘要**     | 自动更新概念的 evolving_summary              | 快速了解一个主题的来龙去脉 |
| **时间层追踪**   | 记录 temporal_events，检测兴趣漂移           | 时间线视图，展示知识演化   |

#### 7.3.2 知识深度的推演（反思引擎）

| 能力             | 实现方式                         | 用户价值                                                      |
| ---------------- | -------------------------------- | ------------------------------------------------------------- |
| **模式发现**     | 识别反复出现的思维模式           | "你最近 2 周频繁提到'性能优化'，共 15 个语义块"               |
| **矛盾检测**     | 发现观点之间的冲突               | "你在 5 月认为'本地模型足够'，但 10 月提到'云端推理不可替代'" |
| **知识缺口识别** | 分析已有知识结构，发现缺失的维度 | "你研究了向量数据库的索引，但尚未涉及'分布式部署'"            |
| **关联推荐**     | 基于已有知识推荐可能感兴趣的领域 | "关注'向量数据库'的用户也关注'RAG 系统'"                      |

#### 7.3.3 知识广度的推演（探索引擎）

| 能力               | 实现方式                             | 用户价值                                     |
| ------------------ | ------------------------------------ | -------------------------------------------- |
| **概念网络可视化** | 力导向图展示概念、主题、语义块的关系 | 直观发现知识之间的隐藏关联                   |
| **主题演化树**     | 展示主题如何从子主题分裂/合并        | 理解知识结构的演化路径                       |
| **跨领域关联**     | 检测不同领域之间的意外关联           | "你关于'本地优先'的想法与'分布式系统'有关联" |

#### 7.3.4 深度探索的交互方式

- **反思流**：AI 主动推送洞察，用户每日查看
- **时间线视图**：选择任意概念/主题，查看其随时间的变化轨迹
- **知识图谱交互**：点击节点探索关联，发现意料之外的连接
- **"为什么"机制**：每个洞察都提供"为什么这么认为"的解释

#### 7.3.5 多源输入

扩展 Journal 记录之外的内容来源，为推演引擎提供更丰富的素材：

- **语音转写**：语音输入自动转写为文本，追加到 Journal（Phase 2+）
- **Web Clip**：浏览器摘录保存为 Markdown，存入 Journal（Phase 2+）
- **Markdown 导入**：批量导入现有 .md 文件到 workspace（Phase 2+）

#### 7.3.6 内容导出

将推演结果和创作成果输出为可交付格式：

- **PDF / HTML 导出**：格式化输出，满足正式交付需求（Phase 3+）

> **目标3 的验证点（Phase 2+）**：用户是否能通过 PenTip 的自动推演，发现自己知识体系中的盲点或矛盾，并据此调整研究方向？是否能在 3 个月内，看到自己知识结构的显著演化？

## 十、护城河与战略定位

### 10.1 护城河

PenTip 的护城河建立在三大核心目标的层层递进之上，最终汇聚为**用户长期认知数据**：

- **目标1（自动整理）**：用户持续在 PenTip 中记录，语义块之间形成密集的语义网络，迁移成本极高
- **目标2（高质量创作）**：知识库与创作工作台深度耦合，作品与知识相互滋养，形成创作惯性
- **目标3（自动推演）**：时间线追踪、矛盾检测、知识缺口识别——这些能力随数据积累而增强，使用越久价值越大

这是未来 AI 时代最有价值的数据层之一，能够形成：

- Personal AI Memory（个人 AI 记忆）
- Long-term Context（长期上下文）
- Cognitive Modeling（认知建模）
- Personalized Agent（个性化智能体）

### 10.2 最终战略定位

PenTip 不应该成为**更好的笔记软件**，而应该成为**AI 时代的长期认知工作台**。

> PenTip 是一个以 Markdown 文件为数据源，以 AI 为智能索引的认知工作台，让碎片知识自动结晶为体系，在创作中自然调用，在思考中持续演化。
