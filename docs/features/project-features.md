# Project 功能需求 — 结构化创作工作台

> 本文档从 [prd.md](prd.md) §3.3 拆分。
> 创作层支持用户按作品组织内容，与 Journal/Wiki 的核心区别：有明确的目标和结构。

---

## 一、项目结构

**项目（Project）与页面（Page）** 构成两级层次结构：

- **项目** = 一个作品级实体，对应 `projects/` 下的一个文件夹。可以是系列文章、小说、研究报告、书籍等
- **页面** = 项目内的具体内容单元，对应一个 `.md` 文件。一个项目由多个页面组成

```
projects/
├── 向量数据库技术调研报告/        # 项目（文件夹）
│   ├── index.md                   # 首页
│   ├── 01-背景与问题定义.md        # 页面（.md 文件）
│   ├── 02-候选方案概览.md
│   ├── 03-多维度对比分析.md
│   └── 04-推荐方案与结论.md
├── 个人小说/                      # 项目（文件夹）
│   ├── index.md                   # 首页（大纲/人物设定）
│   ├── 第一章-启程.md
│   ├── 第二章-迷雾.md
│   └── 第三章-真相.md
└── 产品设计思考/                  # 项目（文件夹）
    ├── index.md
    ├── 本地优先理念.md
    └── 用户隐私保护方案.md
```

### 与 Journal/Wiki 的关系

```
Journal：自由输入，无结构约束
   ↓
Wiki：AI 自动发现结构（概念、主题）
   ↓
Project：用户定义结构，AI 辅助填充
```

---

## 二、项目类型

| 类型     | 结构模板                        | 适用场景               |
| :------- | :------------------------------ | :--------------------- |
| **文章** | index.md + 多章节 .md           | 博客、公众号、技术文章 |
| **报告** | index.md + 背景/分析/结论 .md   | 调研报告、分析报告     |
| **小说** | index.md（大纲/设定）+ 章节 .md | 长篇创作               |
| **Wiki** | index.md（分类导航）+ 条目 .md  | 个人知识库发布         |
| **演示** | index.md + 逐页 .md             | PPT 内容准备           |
| **自由** | 用户自定义结构                  | 灵活创作               |

---

## 三、页面管理

| 操作           | 说明                           |
| :------------- | :----------------------------- |
| **新建页面**   | 在项目内创建新的 .md 文件      |
| **重命名页面** | 修改文件名，同步更新索引       |
| **删除页面**   | 软删除，保留历史记录           |
| **拖拽排序**   | 调整页面在项目中的顺序         |
| **页面大纲**   | 基于 Markdown 标题自动生成导航 |

## 四、创作工作流

### Step 1：创建项目

```
┌─────────────────────────────────────────────────┐
│  新建创作项目                                    │
├─────────────────────────────────────────────────┤
│                                                 │
│  项目名称：[本地语义搜索方案调研报告___________]  │
│                                                 │
│  项目类型：○ 文章  ● 报告  ○ 小说  ○ 自由       │
│                                                 │
│  关联主题：                                      │
│  ☑ 本地语义搜索方案选型（8 语义块）              │
│  ☐ 嵌入模型对比（5 语义块）                     │
│  ☐ 产品本地优先架构（12 语义块）                 │
│                                                 │
│  目标字数：[5000___________]                     │
│                                                 │
│  [AI 生成大纲]  [手动创建]                       │
│                                                 │
└─────────────────────────────────────────────────┘
```

### Step 2：AI 生成大纲

选择关联主题后，AI 自动从知识库召回相关语义块，生成结构化大纲：

```
┌─────────────────────────────────────────────────┐
│  大纲：本地语义搜索方案调研报告                   │
├─────────────────────────────────────────────────┤
│                                                 │
│  1. 背景与问题定义                               │
│     └─ 关联 2 个语义块                          │
│  2. 候选方案概览                                 │
│     2.1 LanceDB                   3 语义块      │
│     2.2 FAISS                     2 语义块      │
│     2.3 ChromaDB                  1 语义块       │
│  3. 多维度对比分析                               │
│     3.1 部署复杂度                2 语义块       │
│     3.2 查询性能                  3 语义块       │
│     3.3 内存占用                  2 语义块       │
│  4. 推荐方案与理由                               │
│     └─ 关联 2 个语义块                          │
│                                                 │
│  [确认大纲]  [调整结构]  [重新生成]               │
│                                                 │
└─────────────────────────────────────────────────┘
```

### Step 3：AI 辅助填充

大纲确认后，进入**分页面编辑模式**。每个页面：

- 左侧：章节编辑区（富文本 / Markdown）
- 右侧：AI 上下文面板，显示关联的语义块和 AI 建议

```
┌──────────────────────────┬──────────────────────┐
│  3.2 查询性能对比         │  AI 上下文           │
│                          │                      │
│  在查询性能方面，我们     │  关联语义块：         │
│  对比了三种方案在         │  · LanceDB ANN 搜索   │
│  10000 条向量上的         │    延迟 < 10ms       │
│  QPS 表现...              │  · FAISS 在同等条件  │
│                          │    下约 15ms         │
│  [AI 续写] [AI 润色]     │  · ChromaDB 约 25ms  │
│                          │                      │
│                          │  AI 建议：            │
│                          │  可以补充索引类型     │
│                          │  对 QPS 的影响分析    │
└──────────────────────────┴──────────────────────┘
```

### Step 4：导出（Phase 3）

多格式导出（PDF / HTML）属于 Phase 3 功能范围，Phase 1 不实现。

## 五、AI 辅助功能

| 功能         | 说明                                     |
| :----------- | :--------------------------------------- |
| **AI 续写**  | 基于上下文和关联语义块，自动续写当前章节 |
| **AI 润色**  | 优化表达、修正语法、统一风格             |
| **AI 摘要**  | 为当前章节生成摘要                       |
| **关联召回** | 自动从知识库召回与当前章节相关的语义块   |
| **结构建议** | 分析当前内容，建议补充或调整章节结构     |

## 六、Phase 1 功能范围

| 功能                       | 优先级 | 说明                            |
| :------------------------- | :----- | :------------------------------ |
| 创建项目 + 关联主题        | P0     | 基础创作项目                    |
| AI 生成大纲                | P0     | 基于关联语义块生成结构          |
| 分章节编辑 + AI 上下文面板 | P0     | 左侧大纲树，中间编辑器，右侧 AI |
| AI 续写                    | P0     | 基于上下文 + 关联语义块自动续写 |
| AI 润色 / 改写             | P0     | 选中文本优化表达                |
| 语义检索引用               | P0     | 创作时搜索历史语义块，一键插入  |
