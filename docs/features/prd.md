# PenTip 产品功能设计文档（PRD）

---

## 一、产品概述

**产品名称**：PenTip

**产品定位**：以 Markdown 文件为数据源，以 AI 为智能索引的认知工作台

**一句话描述**：让碎片知识自动结晶为体系，在创作中自然调用，在思考中持续演化。

**核心理念**：

| 理念                 | 说明                                                          |
| :------------------- | :------------------------------------------------------------ |
| **File First**       | Markdown 文件是真实数据源，用户拥有完整控制权                 |
| **AI Native**        | AI 不是插件，而是工作流本身——嵌入记录、整理、推演、创作全流程 |
| **Local First**      | 数据完全本地可控，隐私安全，离线可用                          |
| **Flow → Structure** | 日志流自然输入，知识体系自动生长                              |

**用户核心交互**：记录 → 整理 → 推演 → 创作。用户只做这些事，其余由 AI 自动完成。

---

## 二、核心交互流程

```
┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐
│   记录    │  →   │   整理   │  →   │   推演    │  →   │   创作   │
│  Record  │      │ Organize │      │  Evolve  │      │  Create  │
└────┬─────┘      └────┬─────┘      └────┬─────┘      └────┬─────┘
     │                 │                 │                 │
  Journal 视图    语义拆分 + 向量化     时间线追踪         项目作品编辑器
                  语义链接 + 概念      反思洞察           AI Skills
  .md 文件持久化      主题聚类          知识缺口识别       语义检索引用
     │                 │                 │                 │
     └─────────────────── AI 自动衔接 ──────────────────────┘
```

### 2.1 用户记录 Journal

用户打开应用，进入今日日志页，直接在页面中编辑 Markdown 内容。每条文本为一个块（Block），内容自动写入 `journal/YYYY-MM-DD.md` 文件。

AI 在后台自动处理：语义拆分 → 生成 embedding 向量 → 与历史语义块进行语义相似度匹配 → 建立语义链接 → 更新 FTS5 全文索引 → 更新概念演化摘要。

### 2.2 AI 整理

AI 自动从用户所有语义块中提取概念实体，建立概念网络。当某个概念簇积累足够多的语义块时，AI 自动触发主题聚类，生成主题建议推送给用户确认。

用户可浏览 AI 自动生成的概念网络和主题聚类。

### 2.3 AI 推演

基于长期积累的语义块数据，AI 自动追踪时间层记录，更新概念演化摘要，进行模式发现和周期性分析。

推演结果以反思（Reflection）形式主动推送给用户，帮助发现思维模式、观点矛盾、知识缺口和兴趣漂移。

### 2.4 创作

用户选择一个主题或手动创建项目，设定目标结构，AI 辅助填充内容，最终导出结构化作品。

创作层与 Journal/Wiki 的核心区别：有明确的目标和结构。

```
Journal：自由输入，无结构约束
   ↓
Wiki：AI 自动发现结构（概念、主题）
   ↓
Project：用户定义结构，AI 辅助填充
```

## 三、核心功能

### 3.1 Journal 记录日志

Journal 采用 **每日日志页** 模式（参考 Logseq 的日志流），每天自动对应一个 `journal/YYYY-MM-DD.md` 文件。用户打开应用默认进入今日日志页，可在页面内自由编辑。


**核心设计**：Journal 采用 **Markdown 文件编辑模式**（参考 Logseq 的日志流），打开即进入 `journal/YYYY-MM-DD.md` 文件的直接编辑。每行为一个块（Block），支持大纲层级、标记语法和行内编辑，无需通过固定输入框创建内容。

**语义块视觉区分**：AI 自动将连续相关的块聚合为语义块。默认状态下，语义块与普通块外观一致，保持页面整洁。鼠标悬浮到语义块区域时，整块呈现浅色背景和卡片轮廓，帮助用户快速识别内容分组。

#### 块（Block）编辑

Journal 的核心交互单元是**块**，每个块对应 Markdown 文件中的一行。

| 操作                | 行为                                                     |
| :------------------ | :------------------------------------------------------- |
| **点击块**          | 进入行内编辑模式，直接修改内容                           |
| **Enter**           | 在当前块下方创建同级新块                                 |
| **Tab / Shift+Tab** | 缩进/提升块层级，形成大纲结构                            |
| **上下方向键**      | 在块之间快速导航                                         |
| **选中多块**        | 批量操作：拖拽排序、复制、删除                           |
| **拖拽块左侧手柄**  | 拖动块到任意位置，调整顺序或层级                         |
| **输入 `#标签`**    | 自动补全已有标签，标记为标签                             |
| **输入 `[[页面]]`** | 自动补全已有页面/概念，创建双向链接                      |
| **输入 `- [ ]`**    | 自动识别为 TODO，支持循环切换：TODO → LATER → NOW → DONE |
| **输入 `>`**        | 自动识别为引用块                                         |
| **输入 `$$`**       | 行内 LaTeX 公式（未来）                                  |
| **粘贴链接**        | 自动抓取标题和摘要（可选）                               |
| **粘贴长文本**      | 自动按空行或语义边界拆分为多个块                         |
| **Ctrl+Z**          | 撤销到上一个操作状态                                     |

**TODO 状态循环**：

```
TODO  →  LATER  →  NOW  →  DONE  →  CANCELED
  ↑                                        │
  └────────────────────────────────────────┘
```

点击 TODO 标记循环切换状态，视觉上 DONE 自动添加删除线。

#### AI 增强（后台自动）

Journal 的 AI 处理在后台无感知进行，不影响用户编辑体验：

1. 块写入 `journal/YYYY-MM-DD.md` 文件后，文件变更检测触发
2. AI 语义拆分 → 生成 embedding 向量
3. 与历史语义块进行语义相似度匹配，建立 semantic_links
4. 提取概念实体，更新 Concept 的 evolving_summary
5. 更新 FTS5 全文索引
6. 更新概念演化摘要

| 功能              | 说明                                                                                                      |
| :---------------- | :-------------------------------------------------------------------------------------------------------- |
| **快捷键 Ctrl+K** | 全局搜索，在任何页面均可触发                                                                              |
| **搜索范围**      | 同时搜索语义块（FTS5 全文）、概念（名称+摘要）、主题（名称+摘要）、作品（名称+描述）、页面（文件名+标签） |

### 3.2 Wiki 查看知识体系

Wiki 是 AI 自动整理的知识体系视图，包含概念网络和主题聚类两大核心模块。

#### 概念网络（Concept Graph）

概念网络是 AI 从用户所有语义块中自动提取的**概念实体及其关联关系**的**气泡图**可视化呈现。

**气泡图数据映射：**

| 气泡特性          | 对应的数据含义                                    |
| :---------------- | :------------------------------------------------ |
| **气泡大小**      | 概念关联的语义块数量（Block 越多，气泡越大）      |
| **气泡位置/距离** | 概念之间的语义相似度（共享 Block 越多，位置越近） |
| **气泡颜色**      | 概念所属的主题（同一主题的概念颜色相近）          |
| **气泡内标签**    | 概念名称                                          |

**可视化示意：**

```
┌─────────────────────────────────────────────────────┐
│  概念网络                                     🔍 搜索 │
├─────────────────────────────────────────────────────┤
│                                                     │
│          ╭─────────────────╮                        │
│         │   向量数据库     │  ← 大气泡（12 Blocks）  │
│          ╰─────────────────╯                        │
│              │                                      │
│    ╭─────────┼──────────╮                          │
│    │         │          │                           │
│ ╭──▼──╮  ╭───▼──╮  ╭───▼──╮                       │
│ │LanceDB│ │IVF-PQ│  │语义搜索│                       │
│ ╰──────╯  ╰──────╯  ╰──────╯                       │
│    │                                              │
│    │   ╭──────────╮                              │

│              ╰──────────╯                           │
```

### 筛选与过滤（Phase 2）

| 功能                  | 说明                                     |
| :-------------------- | :--------------------------------------- |
| **按主题筛选**        | 只显示某个主题下的概念                   |
| **按时间范围筛选**    | 只显示近期有更新的概念（updated_at）     |
| **按 Block 数量筛选** | 只显示关联 Block 数大于 N 的概念         |
| **搜索概念**          | 输入关键词，高亮匹配的气泡，未匹配的淡出 |

### 相似概念合并（Phase 2）

当两个或多个概念语义高度相似（共享 Block 比例超过阈值，如 60%），系统提示建议合并：

| 阶段     | 行为                                                                       |
| :------- | :------------------------------------------------------------------------- |
| **检测** | AI 自动检测语义相似度高的概念对，在气泡图上以虚线边框或闪烁提示            |
| **预览** | 悬停提示区域，高亮显示将被合并的概念及其共享的 Block 列表                  |
| **确认** | 用户确认合并后，选择一个保留的概念名称，或输入新名称                       |
| **结果** | 被合并的概念的 Block 和关联关系全部转移到保留概念下，更新 evolving_summary |

**合并流程示意：**

```
检测到相似概念：「LanceDB」↔「LanceDB 向量库」
  共享 Block 比例：75%
  ┌─────────────────────────────────┐
  │  是否合并这两个概念？            │
  │                                 │
  │  保留名称：○ LanceDB            │
  │           ○ LanceDB 向量库      │
  │           ○ 自定义：________    │
  │                                 │
  │  合并后将包含 15 个语义块        │
  │  [确认合并]  [忽略]  [稍后提醒] │
  └─────────────────────────────────┘
```


#### 反思流（Reflection）← Phase 2

反思是 PenTip 的**"元认知层"**——让系统不仅存储知识，还能分析知识的结构、变化和潜在价值。

**一、反思类型总览**

| 类别     | 反思类型     | 核心价值                 | AI 依赖 |
| :------- | :----------- | :----------------------- | :------ |
| 模式发现 | 热点主题识别 | 发现近期关注焦点         | 中      |
|          | 周期性规律   | 识别记录习惯的周期模式   | 低      |
|          | 高频概念     | 发现反复出现的核心概念   | 低      |
| 趋势分析 | 兴趣漂移     | 追踪关注点的转移         | 中      |
|          | 知识增长     | 展示知识量的积累趋势     | 低      |
|          | 概念演化     | 概念含义的变化轨迹       | 高      |
| 矛盾检测 | 观点冲突     | 发现不同时间的矛盾观点   | 高      |
|          | 目标偏离     | 当前行动与长期目标不一致 | 中      |
| 知识缺口 | 缺失关联     | 发现未建立的关键连接     | 中      |
|          | 延伸探索     | 推荐相关的未知领域       | 高      |
| 行为洞察 | 活跃提醒     | 长期未记录的提醒         | 低      |
|          | 习惯肯定     | 正向强化记录习惯         | 低      |
| 创作启发 | 素材聚合     | 为特定主题聚合可用素材   | 中      |
|          | 灵感触发     | 基于历史记录生成新想法   | 高      |

**二、详细分类与触发逻辑**

**类别一：模式发现（Pattern Discovery）** — 识别用户知识活动中的重复模式

| 类型           | 名称         | 触发逻辑                                | 示例文案                                                                                   |
| :------------- | :----------- | :-------------------------------------- | :----------------------------------------------------------------------------------------- |
| **热点主题**   | 近期关注焦点 | 过去 7 天新增 Block 数量最多的概念/主题 | "你最近一周关于'向量数据库'的讨论热度上升了 80%，新增了 6 个相关 Block。"                  |
| **周期性规律** | 记录节奏分析 | 分析用户历史记录的时间分布              | "你通常在周二和周四记录最多，本周四的记录量比平时高 40%。"                                 |
| **高频概念**   | 核心概念识别 | 全局统计被引用最多的概念                | "你的知识体系中，'本地优先'是出现频率最高的概念（47 次引用），其次是'语义搜索'（32 次）。" |

**类别二：趋势分析（Trend Analysis）** — 追踪知识在时间维度上的变化

| 类型         | 名称          | 触发逻辑                           | 示例文案                                                                                        |
| :----------- | :------------ | :--------------------------------- | :---------------------------------------------------------------------------------------------- |
| **兴趣漂移** | 关注转移检测  | 对比不同时间段的概念热度排序变化   | "你的关注点正在从'前端框架'（-45%）转向'AI 推理引擎'（+62%），这种趋势已持续 3 周。"            |
| **知识增长** | 知识积累报告  | 统计新增 Block/概念/主题的数量变化 | "本月你新增了 23 个 Block、5 个概念和 2 个主题，知识体系增长率为 12%，与上月持平。"             |
| **概念演化** | 观点/含义演化 | 对比同一概念在不同时间的描述变化   | "你关于'本地优先'的理解从'数据存本地'演变为'完整的隐私保护理念'，这期间新增了 8 个相关 Block。" |

**类别三：矛盾检测（Contradiction Detection）** — 发现知识体系中的不一致或冲突

| 类型         | 名称             | 触发逻辑                                | 示例文案                                                                                                 |
| :----------- | :--------------- | :-------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| **观点冲突** | 观点矛盾发现     | 在同一主题/概念下，识别出逻辑矛盾的表述 | "你在 5 月 10 日写道'本地模型已足够'，但在 6 月 15 日写道'复杂推理必须上云端'。这两个观点存在潜在矛盾。" |
| **目标偏离** | 行动与目标不一致 | 用户设定的目标 vs 实际记录内容的偏差    | "你本季度的目标是'掌握向量数据库'，但最近 2 周的相关记录仅占全部记录的 5%，建议重新聚焦。"               |

**类别四：知识缺口（Knowledge Gap）** — 发现知识体系中缺失或薄弱的部分

| 类型         | 名称         | 触发逻辑                                               | 示例文案                                                                                              |
| :----------- | :----------- | :----------------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| **缺失关联** | 潜在连接建议 | 检测到两个高频概念从未或很少同时出现，但语义上高度相关 | "你经常讨论'LanceDB'和'IVF-PQ 索引'，但从未将'LanceDB'与'分布式部署'关联起来。是否有意探索这个方向？" |
| **延伸探索** | 未知领域推荐 | 基于已有知识推荐相邻领域                               | "你已深入研究'向量数据库'，建议探索'RAG 系统'——该领域与你的知识重叠度高，且你当前没有相关记录。"      |

**类别五：行为洞察（Behavioral Insight）** — 关注用户的记录行为和习惯

| 类型         | 名称         | 触发逻辑                             | 示例文案                                                                                |
| :----------- | :----------- | :----------------------------------- | :-------------------------------------------------------------------------------------- |
| **活跃提醒** | 记录断点提醒 | 检测到连续 N 天（如 7 天）无新增记录 | "你已经 7 天没有记录新内容了。上次记录是关于'向量数据库选型'的思考，要继续这个话题吗？" |
| **习惯肯定** | 正向强化     | 检测到连续记录超过 N 天              | "你已经连续 30 天保持记录习惯，累计记录了 156 个 Block。这是一个了不起的成就！"         |

**类别六：创作启发（Creation Inspiration）** — 基于已有知识激发新的创作

| 类型         | 名称         | 触发逻辑                           | 示例文案                                                                                                                   |
| :----------- | :----------- | :--------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **素材聚合** | 主题素材盘点 | 针对某个已有主题，汇总所有可用素材 | "你的'向量数据库'主题下已有 23 个 Block 和 5 个概念，可以整理为一篇技术调研报告。素材覆盖了选型对比、性能测试和部署方案。" |
| **灵感触发** | 跨领域灵感   | 将两个不相关领域结合，生成新想法   | "你同时关注'咖啡文化'和'本地优先架构'——'本地咖啡品鉴指南'和'本地优先 App'这两个方向是否有交叉点？"                         |

**三、反思的数据模型**

```sql
CREATE TABLE reflections (
    id TEXT PRIMARY KEY,
    type TEXT NOT NULL,              -- 反思类型（见上表）
    title TEXT NOT NULL,             -- 反思标题
    content TEXT NOT NULL,           -- 反思内容（用户可读的自然语言）
    confidence REAL DEFAULT 0.0,     -- AI 置信度（0-1）
    severity TEXT DEFAULT 'info',    -- 严重程度：info / warning / important
    status TEXT DEFAULT 'pending',   -- pending / read / archived
    related_block_ids TEXT,          -- JSON 数组，关联的 Block ID
    related_concept_ids TEXT,        -- JSON 数组，关联的概念 ID
    related_topic_ids TEXT,          -- JSON 数组，关联的主题 ID
    metadata TEXT DEFAULT '{}',      -- 扩展数据（如数值对比等）
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

### 3.3 Project 按作品创作

创作层支持用户按作品组织内容。**项目（Project）与页面（Page）** 构成两级层次结构：

- **项目** = 一个作品级实体，对应 `projects/` 下的一个文件夹。可以是系列文章、小说、研究报告、书籍等
- **页面** = 项目内的具体内容单元，对应一个 `.md` 文件。一个项目由多个页面组成

```
projects/
├── 向量数据库技术调研报告/        # 项目（文件夹）
│   ├── index.md                   # 首页
│   ├── 01-背景与问题定义.md        # 页面（.md 文件）
│   ├── 02-候选方案概览.md
│   ├── 03-多维度对比分析.md
│   └── 04-推荐方案与结论.md
├── 个人小说/                      # 项目（文件夹）
│   ├── index.md                   # 首页（大纲/人物设定）
│   ├── 第一章-启程.md
│   ├── 第二章-迷雾.md
│   └── 第三章-真相.md
└── 产品设计思考/                  # 项目（文件夹）
    ├── index.md
    ├── 本地优先理念.md
    └── 用户隐私保护方案.md
```

#### 项目类型

| 类型     | 结构模板                        | 适用场景               |
| :------- | :------------------------------ | :--------------------- |
| **文章** | index.md + 多章节 .md           | 博客、公众号、技术文章 |
| **报告** | index.md + 背景/分析/结论 .md   | 调研报告、分析报告     |
| **小说** | index.md（大纲/设定）+ 章节 .md | 长篇创作               |
| **Wiki** | index.md（分类导航）+ 条目 .md  | 个人知识库发布         |
| **演示** | index.md + 逐页 .md             | PPT 内容准备           |
| **自由** | 用户自定义结构                  | 灵活创作               |

#### 页面管理

| 操作           | 说明                           |
| :------------- | :----------------------------- |
| **新建页面**   | 在项目内创建新的 .md 文件      |
| **重命名页面** | 修改文件名，同步更新索引       |
| **删除页面**   | 软删除，保留历史记录           |
| **拖拽排序**   | 调整页面在项目中的顺序         |
| **页面大纲**   | 基于 Markdown 标题自动生成导航 |

```
│  10000 条向量上的         │    延迟 < 10ms       │
│  QPS 表现...              │  · FAISS 在同等条件  │
│                          │    下约 15ms         │
│  [AI 续写] [AI 润色]     │  · ChromaDB 约 25ms  │
│                          │                      │
│                          │  AI 建议：            │
│                          │  可以补充索引类型     │
│                          │  对 QPS 的影响分析    │
└──────────────────────────┴──────────────────────┘
```

**AI 辅助功能**：

| 功能         | 说明                                     |
| :----------- | :--------------------------------------- |
| **AI 续写**  | 基于上下文和关联语义块，自动续写当前章节 |
| **AI 润色**  | 优化表达、修正语法、统一风格             |
| **AI 摘要**  | 为当前章节生成摘要                       |
| **关联召回** | 自动从知识库召回与当前章节相关的语义块   |
| **结构建议** | 分析当前内容，建议补充或调整章节结构     |

**Step 4：导出** ← Phase 3

多格式导出（PDF / HTML）属于 Phase 3 功能范围，Phase 1 不实现。

## 四、其他功能

### 4.1 首次启动欢迎页

首次启动时，引导用户完成以下配置：

1. **选择工作空间**：指定 Markdown 文件存储目录
2. **启用本地智能**：下载 embedding + reranker + 语言模型（约 4.5 GB）
3. **启用云端智能**（可选）：选择服务商并填入 API Key，设置月度限额
4. **快速上手**：展示核心交互流程，引导用户完成第一条记录

### 4.2 设置

| 设置项            | 说明                                          |
| :---------------- | :-------------------------------------------- |
| **本地模型管理**  | 模型下载/切换/删除的可视化管理                |
| **云端 API 配置** | OpenAI 兼容 API Key + Base URL 配置           |
| **智能模式**      | 独立开启/关闭本地智能和云端智能               |
| **模型路由**      | 调整任务路由优先级（如"强制所有 LLM 走云端"） |
| **通用设置**      | 语言（中/英文）、主题、快捷键                 |
| **数据管理**      | 工作空间路径、数据库迁移、备份与恢复          |

### 4.3 升级

- **版本更新检查**：自动检测新版本，提示用户下载
- **模型更新**：当有新模型可用时，在模型管理器中提示
- **功能迭代**：Phase 1 → Phase 2（反思流、跨设备同步）→ Phase 3（多格式导出、插件系统）
