# MVP Sprint 计划

---

## 一、总览

### 1.1 核心目标

**实现 Phase 1 三大核心目标：零散知识自动整理（目标1）+ 基于知识体系输出高质量创作（目标2）+ 概念提取（目标1 增强）。**

### 1.2 技术栈

| 层级       | 技术选型                                                                              |
| ---------- | ------------------------------------------------------------------------------------- |
| 桌面框架   | Electron 34+                                                                          |
| 前端       | Vue 3 + TypeScript + Naive UI + Pinia + Vue Router                                    |
| 构建工具   | Vite + vite-plugin-electron                                                           |
| 数据库     | SQLite（better-sqlite3，WAL 模式，FTS5 全文搜索）                                     |
| 向量数据库 | LanceDB（本地嵌入式，IVF-PQ 索引）                                                    |
| AI 模型    | jina-embeddings-v3（Embedding）、bge-reranker-v2-m3（重排序）、Qwen3.5-4B（本地 LLM） |
| 包管理     | pnpm                                                                                  |

### 1.3 执行原则

1. **Phase 1 聚焦**：专注目标1（自动整理）+ 目标2（高质量创作），不做目标3 推演功能
2. **File First**：Markdown 文件为真实数据源，SQLite + LanceDB 为 AI 索引层
3. **Local First**：所有数据保存在本地，用户隐私第一
4. **快速迭代**：每周产出可演示版本，收集早期用户反馈
5. **开源驱动**：GitHub Repo 持续更新，鼓励社区贡献
6. **四线并行**：每周同时推进 开发 / AI 功能 / UI/UX / 推广社区

### 1.4 总工期

**6 周**，每周为一个 Sprint。

## 二、技术架构决策

### 2.1 存储架构：文件优先，数据库索引

| 决策       | 选型              | 理由                                               |
| ---------- | ----------------- | -------------------------------------------------- |
| 真实数据源 | Markdown 文件系统 | 用户数据 = .md 文件，可直接编辑、备份、迁移        |
| 结构化索引 | SQLite            | 零配置、跨平台、Electron 原生支持、FTS5 全文搜索   |
| 向量存储   | LanceDB           | 嵌入式部署、IVF-PQ 索引、毫秒级 ANN 搜索、增量更新 |

### 2.2 AI 模型选型

| 用途          | 模型                   | 理由                                   |
| ------------- | ---------------------- | -------------------------------------- |
| Embedding     | jina-embeddings-v3     | 1536 维，中英文效果好，支持本地部署    |
| Reranker      | bge-reranker-v2-m3     | 提升语义搜索准确性，多语言支持         |
| 本地 LLM      | Qwen3.5-4B             | 4B 参数可在 8GB 内存设备运行，中文优秀 |
| 语义拆分/总结 | Qwen3.5-4B（本地优先） | 本地推理，隐私保护，离线可用           |
| 云端增强      | OpenAI / Claude API    | 用户自带 API Key，复杂任务可选增强     |

### 2.3 架构约束

- **最低硬件**：8GB 内存，Windows / macOS / Linux
- **离线优先**：核心 AI 能力（Embedding、LLM 推理）本地运行，云端 API 为可选增强
- **模型首次引导下载**：首次启动引导用户选择启用本地智能（全部 3 个模型）和/或云端智能（配置 API Key）

## 五、风险与缓解

| 风险                        | 影响 | 概率 | 缓解措施                                             |
| --------------------------- | ---- | ---- | ---------------------------------------------------- |
| 本地模型推理性能不足        | 高   | 中   | Week 1 即验证 Qwen3.5-4B 在 8GB 设备上的推理速度     |
| jina-embeddings-v3 下载失败 | 中   | 低   | 提供国内镜像下载源，支持手动导入模型文件             |
| LanceDB Node.js 兼容性      | 高   | 低   | Week 1 验证 LanceDB 在 Electron 环境的可用性         |
| better-sqlite3 编译问题     | 高   | 中   | 锁定 Node.js 版本，提供 prebuild 二进制              |
| Electron 打包体积过大       | 中   | 中   | 模型文件与安装包分离，按需下载                       |
| 语义链接准确率低            | 中   | 中   | bge-reranker 重排序兜底，Week 3 即收集准确率反馈     |
| 时间不足                    | 高   | 中   | 严格 Phase 1 范围控制，非目标1/目标2核心需求一律延后 |

## 七、后续规划（Phase 2+）

Phase 1 验证通过后，按 MRD 路线图启动 Phase 2 和 Phase 3：

### Phase 2（1 → 10）：目标3 + 目标2 增强

- **目标3 新增**：反思流（模式发现、矛盾检测、知识缺口识别、兴趣漂移检测）、时间层追踪、演化摘要、概念演化追踪
- **目标2 增强**：概念网络可视化（力导向图）、相似概念合并、上下文自动召回
- **跨设备同步**：Operation-based Sync（Pro 功能）

### Phase 3（10 → 100）：完整认知平台

- **新增**：跨领域关联、主题演化树、创作启发（灵感触发）
- **多源输入**：语音转写、Web Clip、Markdown 批量导入
- **多格式导出**：PDF / HTML 导出
- **插件系统**：Data / Cognitive / Output 三层插件架构
- **移动端**：iOS / Android 快速捕获（Pro 功能）
- **平台扩展**：Team Graph、Agent Marketplace
