# 产品经理（PM）使用场景

> 面向角色：互联网/软件产品经理（PM）、需求分析师、产品负责人（PO）
> 抽象维度：**日常工作流** + **输出文档** + **PenTip 能力映射**

---

## 一、PM 工作日常抽象

产品经理的工作本质是 **信息收集 → 结构化沉淀 → 决策推演 → 协作交付** 的循环。其痛点在于：

| 痛点 | 描述 |
| :--- | :--- |
| 信息碎片化 | 需求来自用户访谈、竞品截图、老板口头、数据看板、行业报告……散落各处 |
| 重复造轮子 | 同类需求文档反复从零起手，历史经验难复用 |
| 决策无沉淀 | 为什么砍掉某需求、为什么选 A 方案——决策依据随会议结束而蒸发 |
| 知识不连续 | 调研过的竞品、写过的分析，下次用到时找不到 |
| 上下文切换成本 | 在飞书/Notion/Axure/Visio/Confluence 间反复跳转 |

PenTip 的 **Journal 自由记录 + Wiki 自动结晶 + Project 结构化创作 + 语义链接 + 反思流** 五件套，恰好对应 PM 工作流的每一环。

---

## 二、PM 典型工作流场景

### 场景 1：需求收集与初步整理

**日常工作**

- 上午参加用户访谈，记录用户原话与痛点
- 下午收到老板微信语音"加个会员体系"，快速记下背景
- 晚上刷到竞品新功能截图，丢进收藏夹
- 数据同学发来一份漏斗数据，截图保存

**PenTip 用法**

所有输入统一进入 **Journal 今日日志页**，以 Block 为最小单位：

```markdown
# 2026-08-08

## 用户访谈 - 电商商家
- 商家A："优惠券叠加规则太复杂，算不清能省多少"
- 商家B："希望后台能直接看到每个SKU的毛利，而不是导出Excel算"
- 痛点关键词：优惠券规则 / 毛利可视化

## 老板需求
- 会员体系，Q3必须上线
- 背景：竞品X上周发布了会员日，DAU涨了15%

## 竞品观察
- 竞品X会员体系截图 ![screenshot]
- 三级会员：普通/银卡/金卡，权益差异在折扣力度和专属客服

## 数据
- 首页到支付页转化率 12% → 8%（本周下降）
- 疑似受新版首页改版影响
```

**AI 自动处理**

- 每个 Block 自动生成 Embedding，与历史语义块匹配
- "优惠券规则" 自动关联到 3 个月前另一商家的反馈
- "会员体系" 自动归入新主题，后续相关输入自动归集
- "转化率下降" 与首页改版的相关性被语义链接捕捉

**价值**：零组织成本，所有碎片输入自动汇入知识网络。

### 场景 2：竞品分析与知识沉淀

**日常工作**

- 长期跟踪 3-5 个竞品
- 每次分析从新建文档开始，重复描述产品定位
- 半年后想找"竞品X上次大版本更新分析"，翻遍文件夹

**PenTip 用法**

竞品分析既是 **Project**（有目标的输出物），也是 **Wiki**（持续沉淀的知识）。

Journal 阶段：每次观察到竞品动态，随手记 Block。

```
- 竞品X 8.2版本新增"商家成长体系"，引导商家完成认证任务获流量加权
- 竞品Y砍掉了直播功能，疑似战略收缩
```

Wiki 阶段：AI 自动将分散的竞品观察聚类为 **竞品X主题**、**竞品Y主题**，并提取概念实体（功能模块、战略动作、用户分层）。

Project 阶段：撰写《Q3竞品分析报告》时，AI 语义检索自动召回所有相关 Block，按时间线排列，PM 只需组织结构与下结论。

**价值**：竞品知识持续累积，报告写作从"从零起手"变为"组织已有素材"。

### 场景 3：需求文档（PRD）撰写

**日常工作**

- PRD 是 PM 最高频输出，结构固定但内容易遗漏
- 历史 PRD 中的功能逻辑、异常处理可复用，但难检索
- 评审时被开发追问"上次为什么这么设计"，答不上来

**PenTip 用法**

PRD 作为 **Project**，利用 Skills 辅助生成。

**步骤**

1. 在 Journal 中记录需求背景、用户故事、约束条件（Block 形式）
2. 创建 Project《XX功能 PRD》，定义章节结构（背景/目标/用户故事/功能详述/流程图/异常处理/数据指标）
3. 调用 AI Skill `prd-draft`，AI 基于语义检索自动填充：
   - 从历史 Block 中召回相关用户原话、调研结论
   - 从历史 PRD 中复用同类功能的异常处理模板
   - 从竞品主题中提取对标方案
4. PM 聚焦于 **决策与边界条件**，AI 负责素材组装

**反思流辅助**

- AI 自动发现："本次PRD的用户故事与2个月前的调研结论存在矛盾"
- AI 自动发现："该功能在去年Q4曾评审过被否决，原因是ROI不足，是否已改变？"

**价值**：PRD 不再是孤立文档，而是知识网络的产出节点，决策有据可查。

### 场景 4：版本规划与 Roadmap

**日常工作**

- 季度初制定 Roadmap，平衡需求优先级、资源、战略目标
- 需求池来自上百条零散输入，归类与排序耗时
- 规划完成后需求变更频繁，Roadmap 维护成本高

**PenTip 用法**

利用 **Topic 主题聚类** 与 **反思流** 辅助规划。

- AI 自动将 Journal 中累积的需求 Block 聚类为主题（如"商家工具"、"会员体系"、"数据看板"）
- 每个主题自动生成摘要与时间线，PM 直观看到需求密度与演化趋势
- 反思流提示："会员体系相关需求近2个月增长300%，建议优先级提升"
- Roadmap 作为 Project 输出，AI 自动关联主题中的具体需求条目

**价值**：从"凭感觉排优先级"到"基于需求密度与演化趋势的客观依据"。

### 场景 5：项目跟进与会议纪要

**日常工作**

- 每日站会、评审会、周会，产出大量会议纪要
- 决策与行动项散落，跟踪困难
- 跨部门沟通结论难追溯

**PenTip 用法**

会议纪要进入 Journal，AI 自动提取行动项与决策点。

```markdown
## 8.8 需求评审 - 会员体系
- 决策：三级会员改为两级，砍掉金卡
- 原因：金卡权益与银卡差异不足，ROI低
- 行动项：@张三 8.10前更新PRD；@李四 8.12前出交互稿
- 风险：支付侧联调依赖，需提前对齐
```

- AI 自动建立"会员体系"语义链接，串联所有相关会议与需求
- 反思流按周/月汇总决策与行动项完成情况

**价值**：会议纪要不再沉睡，决策链路可追溯。

---

### 场景 6：数据分析与洞察

**日常工作**

- 每日看数据看板，发现异常需归因
- 数据分析报告结论易遗忘，下次同类问题重复分析
- 数据洞察与产品决策之间缺少沉淀桥梁

**PenTip 用法**

数据观察以 Block 形式进入 Journal，AI 自动关联历史洞察。

```
- 8.8 转化率下降至8%，同期首页改版上线
- 8.1 转化率12%，首页改版前基线
- 假设：新版首屏 CTA 位置下移导致曝光下降
```

- AI 自动链接到 3 个月前类似改版的归因记录
- 反思流提示："这是本季度第3次改版后转化率波动，建议建立改版数据基线规范"

**价值**：数据洞察持续累积，避免重复归因，形成产品直觉的数字化外脑。

| **流程图/状态机** | Project（图文混排） | AI 辅助识别关键节点与分支 | 历史流程 Block |

## 六、核心价值主张（面向 PM）

1. **零组织成本的输入**：所有碎片信息进入 Journal，AI 自动归类，PM 无需先想"放哪儿"
2. **知识自动结晶**：竞品、需求、用户反馈自动聚类为主题，随时间累积成知识体系
3. **决策链路可追溯**：每个需求/砍需的背后依据，通过语义链接随时召回
4. **报告写作从组装开始**：PRD/竞品报告/调研报告不再从空白页起手，AI 召回相关素材
5. **产品直觉数字化**：反思流持续发现模式与矛盾，成为 PM 的"第二大脑"
6. **数据本地私有**：商业敏感的调研数据、竞品分析、未公开 Roadmap 完全本地存储

## 七、与竞品工具的差异

| 维度 | Notion / 飞书文档 | Axure / 墨刀 | Confluence | **PenTip** |
| :--- | :--- | :--- | :--- | :--- |
| 信息组织 | 手动建库/标签 | 仅原型 | 手动目录 | **AI 自动语义归类** |
| 知识关联 | 手动双链 | 无 | 手动双链 | **AI 自动语义链接** |
| 碎片输入 | 需先建页面 | 不支持 | 需建页面 | **Journal Block 即记** |
| 知识演化 | 无 | 无 | 版本树 | **反思流自动推演** |
| 素材复用 | 手动搜索 | 手动复制 | 手动搜索 | **AI 语义检索召回** |
| 数据隐私 | 云端 | 云端 | 云端 | **本地优先** |

## 八、上手建议（PM 角色路径）

1. **第一周**：所有会议纪要、用户访谈、需求草记统一写入 Journal，不分类
2. **第二周**：观察 Wiki 中 AI 自动生成的主题与概念，验证归类是否符合直觉
3. **第三周**：选择一个待写 PRD，创建 Project，体验 AI 召回历史素材
4. **第四周**：查看反思流，发现需求模式与决策矛盾
5. **持续**：形成"Journal 输入 → Wiki 沉淀 → Project 输出 → Reflection 反哺"的闭环
